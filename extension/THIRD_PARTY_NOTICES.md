## Terminology content bundled with the package

### HL7 Terminology (THO)

- **Source:** FHIR package `hl7.terminology.r4` 7.5.0, published by HL7 International,
  Vocabulary Work Group. Its manifest declares `CC0-1.0`.
- **Where it is:** `src/providers/presets/hl7-code-systems.json`, generated by
  `tools/generate-hl7-code-systems.mjs` in the source repository.
- **Content:** 929 `CodeSystem` resources.
- **Excerpts from other standards:** Some of these code systems excerpt or adapt other
  standards, for example DICOM PS3.16, ISO TS 21089-2017, ASTM E1762-95 and IHE. The
  copyright statement of each code system is kept unchanged in its `CodeSystem.copyright`
  element. Check it before you redistribute that code system on its own.
  `http://terminology.hl7.org/CodeSystem/time-period-ranges` is adapted from content
  published by IHE International, Inc. (copyright 2015) and used under the Creative Commons
  Attribution 4.0 International licence (CC BY 4.0).
- **Excluded from the bundle:** The following code systems are part of the HL7 package but
  belong to third parties. They are not redistributed here:
  - `http://www.ada.org/snodent` (SNODENT, American Dental Association)
  - `http://terminology.hl7.org/CodeSystem/ADAUniversalToothDesignationSystem` (American
    Dental Association)
  - `http://terminology.hl7.org/CodeSystem/ADAToothSurfaceCodes` (American Dental
    Association)
  - `http://terminology.hl7.org/CodeSystem/v3-HealthcareProviderTaxonomyHIPAA` (NUCC Health
    Care Provider Taxonomy; retired)
  - `http://terminology.hl7.org/CodeSystem/color-names` and
    `http://terminology.hl7.org/CodeSystem/color-rgb` (CSS colours, World Wide Web Consortium)

  If you need them, license them from their owner and serve them from your own terminology
  server. The installed `hl7.terminology.r4` dependency still contains these files. Default
  package discovery (the Vite plugin, the `fdh-terminology-discover` CLI and
  `packageAutoDiscovery`) leaves them out like the bundled preset, but packages you select
  explicitly are not filtered; importing them that way needs their owners' licences.

### IHE Deutschland XDS value sets and KDL

These two packages are **dependencies**, not part of this package's tarball. Your package
manager installs them next to this package. `src/providers/presets/index.js` imports their
`CodeSystem` resources, so a bundler copies that content into your application.

| Content | Source package | Publisher | Licence declared by the package |
| --- | --- | --- | --- |
| IHE XDS `classCode` and `typeCode` | `de.ihe-d.terminology` 3.0.1 | IHE Deutschland e.V. | none |
| KDL — Klinische Dokumentenklassen-Liste 2026 | `dvmd.kdl.r4` 2026.0.0 | DVMD e.V. (copyright "2026 DVMD e.V.") | none |

Neither package states a licence. Before you redistribute an application that contains them,
check the publishers' terms or ask the publishers. To leave them out, pass
`disabledProviderIds: ['ihe-xds-class', 'ihe-xds-type', 'kdl']`. Your bundler will still
include the content unless you also replace the bundled presets.

## Terminologies that are not included

The package contains **no SNOMED CT, LOINC, ICD-10-GM, OPS or ATC content**: no codes,
display names, descriptions or hierarchies. It does not preconfigure a terminology server for
them. They are available only after you set `serverConfig.fhirBaseUrl` to a server you are
licensed to use. For SNOMED CT you must also set `snomedConfig.edition` to the edition covered
by your licence.

### Public terminology servers

A terminology server you connect has its own terms of use, in addition to the publishers'
licences. HL7 Deutschland's public server `https://tx.fhir.de/fhir`, for example, is meant for
FHIR tooling, software development, validation and non-commercial research, and high-volume
automated querying needs prior arrangement. See its [terms of use](https://tx.fhir.de/de/terms),
[licences](https://tx.fhir.de/de/licenses) and [privacy statement](https://hl7.de/datenschutz/).
