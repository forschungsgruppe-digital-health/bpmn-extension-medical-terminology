This package is an open-source plugin for **bpmn-js** process editors (not a standalone
application). It lets teams attach standardized, machine-readable medical codes — such as
SNOMED CT, LOINC, ICD-10-GM, OPS, ATC, IHE XDS, KDL, or HL7 — directly to BPMN elements inside
the `.bpmn` file, without changing BPMN itself.

Want to see how it works in practice? Open the interactive demo, click any element in the
diagram, and explore the **Medical terminology** panel, `MT` badges, and generated BPMN
comments:

## What problem does it solve?

A task label such as `CT chest` is understandable to a person, but software cannot reliably
match it with `CT-Thorax`. A terminology annotation adds an unambiguous system URI, code,
optional version, and display text right next to the element:

```xml
<bpmn:task id="Task_CT" name="CT chest">
  <bpmn:extensionElements>
    <mt:annotations>
      <mt:annotation id="mt-ann-1">
        <mt:coding system="http://snomed.info/sct"
                   code="169069000"
                   display="Computed tomography of chest" />
      </mt:annotation>
    </mt:annotations>
  </bpmn:extensionElements>
</bpmn:task>
```

The diagram and BPMN process semantics remain unchanged. All clinical semantics live inside
standard `bpmn:extensionElements` under the versioned `mt:` namespace
`https://forschungsgruppe-digital-health.github.io/bpmn-extension-medical-terminology/ns/terminology/v1`.

## Is it a good fit?

| You need to… | Fit |
| --- | --- |
| Add coded clinical meaning to BPMN elements | **Yes** — this is the core use case |
| Search terminology from a bpmn-js properties panel | **Yes** |
| Store annotations in the `.bpmn` file instead of a sidecar | **Yes** |
| Work offline with bundled or installed FHIR CodeSystems | **Yes** |
| Show visual `MT` badges or optional BPMN comments for annotations | **Yes** — included in the bpmn-js integration |
| Use the XML format from Camunda or a custom BPMN tool | **Yes**, if the tool preserves unknown extension elements |
| Generate FHIR resources from a process model | **Not included**; the annotations can be input to your own mapping |
| Execute or simulate a process | **No** |
| Obtain a terminology licence or hosted terminology server | **No** |

## What you need before adopting

- **Host application or BPMN tool:** For interactive search and editing, integrate the package
  into a bundler-based `bpmn-js` web application. If you use Camunda or another BPMN editor,
  you can exchange the XML format directly without installing the JavaScript package.
- **Terminology sources and licences:** Offline search works out of the box with bundled HL7,
  IHE XDS, and KDL code systems. For production use with SNOMED CT, LOINC, ICD-10-GM, OPS, or
  ATC, your organisation must hold the required publisher licences and connect its own
  terminology server (the public demo server is for evaluation only). See
  [Licensing & terminology rights](/licensing/).
- **Data protection:** Annotations describe clinical *processes* with standardized codes and
  short notes — never enter or store patient data in BPMN models.

## Choose your integration path

### 1. bpmn-js modeler: full interactive setup

First follow the [installation instructions](/compatibility/#installation) (stable releases are
published on GitHub Packages; release candidates are staged on npm). Then wire the standard
bpmn-js properties panel together with the terminology moddle descriptor, UI module, and
terminology services:

```js
import BpmnModeler from 'bpmn-js/lib/Modeler';
import {
  BpmnPropertiesPanelModule,
  BpmnPropertiesProviderModule
} from 'bpmn-js-properties-panel';
import {
  TerminologyModdleDescriptor,
  TerminologyPropertiesPanelModule,
  createDefaultTerminologyModule
} from '@forschungsgruppe-digital-health/bpmn-extension-medical-terminology';

import 'bpmn-js/dist/assets/diagram-js.css';
import 'bpmn-js/dist/assets/bpmn-js.css';
import '@bpmn-io/properties-panel/dist/assets/properties-panel.css';
import '@forschungsgruppe-digital-health/bpmn-extension-medical-terminology/properties-panel.css';

const modeler = new BpmnModeler({
  container: '#canvas',
  propertiesPanel: { parent: '#properties' },
  additionalModules: [
    BpmnPropertiesPanelModule,
    BpmnPropertiesProviderModule,
    TerminologyPropertiesPanelModule,
    createDefaultTerminologyModule()
  ],
  moddleExtensions: {
    mt: TerminologyModdleDescriptor
  }
});
```

`createDefaultTerminologyModule()` supplies the searchable providers and automatically enables
`MT` badges and generated BPMN comments. See [Properties panel](/properties-panel/) and
[Configuration](/configuration/) to point at your own FHIR/Snowstorm server or switch to
offline-only mode.

### 2. JavaScript without the UI

Use the exported moddle descriptor and annotation helpers when your application reads, writes,
or queries annotations programmatically without rendering the properties panel. The package
ships raw ESM for bundler-based builds. Start with the [API reference](/api/) and
[Compatibility](/compatibility/).

### 3. Camunda or another BPMN framework

The UI integration is specific to bpmn-js, but the XML format is framework-independent. Any
tool can read and write the same `mt:` elements directly as long as it preserves unknown
`bpmn:extensionElements` on save. See [XML schema](/schema/) and the generated
[namespace v1 reference](/ns/terminology/v1/).
