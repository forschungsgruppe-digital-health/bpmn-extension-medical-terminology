## Versioning policy

The `v1` segment versions the serialized XML contract, not the npm package.
Ordinary package releases and backward-compatible additions keep this URI unchanged.
An incompatible removal, rename or semantic change requires maintainer approval,
a new namespace version and a documented migration path. Package releases remain
in the `0.x` series until the project deliberately declares a stable public release.

The extension family follows the pattern
`https://forschungsgruppe-digital-health.github.io/<repository>/ns/<extension>/v<format-major>`.
The companion FHIR-mapping extension therefore owns its namespace below its own
GitHub Pages repository rather than reusing this terminology namespace.

## Previous development namespace

Development versions used `https://clinical-bpmn.org/terminology/v1`, which was also
used by the incompatible public predecessor `bpmn-js-clinical-semantics`. This project
had no users or external BPMN files when the authority changed, so repository fixtures
were updated in place and no legacy reader or migration tool is provided. Files from
the predecessor must not be relabelled: its annotation model is structurally different.

See [ADR-0004](https://github.com/forschungsgruppe-digital-health/bpmn-extension-medical-terminology/blob/main/docs/adr/0004-namespace-authority-and-versioning.md)
for the authority, compatibility and family-wide naming decision.
